# 다중 에이전트 기반 신용위험 검토 구조 설계

## 목적

본 문서는 상장기업 신용위험 조기경보 프로젝트의 후속 단계에서 사용할
다중 에이전트 구조를 정리한 설계 문서이다.

기존 실험에서는 정량 모델 이후에 별도의 단일 LLM 해석 단계를 두고,
그 다음에 다시 복수의 에이전트가 판단하는 3단 구조를 검토했다.
그러나 중간 해석 단계를 따로 두면 역할이 중복되고, 입력과 출력의 책임 경계가
불명확해질 수 있다.

이에 따라 프로젝트 구조를 다음과 같이 단순화한다.

1. XGBoost 기반 정량 예측
2. 다중 에이전트 기반 종합 검토

즉, 정량 예측은 모델이 담당하고, 정성 검토와 최종 심사 메모 작성은
에이전트 계층이 담당하는 구조를 목표로 한다.

## 전체 구조

```text
정량 데이터 입력
  -> XGBoost 예측
  -> 설명용 입력 번들 생성
  -> Quant Analyst
  -> Event Researcher
  -> Manager
  -> 최종 심사 메모 / 보고서
```

## 에이전트 구성

### 1. Quant Analyst

역할:
- XGBoost 예측 결과를 재무 관점에서 해석
- 위험확률, 주요 변수 기여도, 핵심 재무비율을 바탕으로 정량적 위험 요약 작성

입력:
- 기업 기본 정보
- 예측확률
- 예측 라벨
- SHAP 상위 변수
- 핵심 재무지표
- 시장/산업 비교 결과

출력:
- 정량 기반 심사 메모
- 핵심 위험 요인 3개
- 완화 요인 2개
- 추가 점검 필요 지표

### 2. Event Researcher

역할:
- 최근 뉴스, 공시, 외부 텍스트 자료를 바탕으로 비재무 리스크 정리
- 정량 모델이 반영하지 못한 최신 이슈 탐지

입력:
- 기업명
- 종목코드
- 수집된 뉴스 요약
- 공시 이벤트 요약
- 필요 시 산업/거시 관련 참고 자료

출력:
- 최근 이슈 요약
- 치명 리스크 여부
- 정량 결과를 약화 또는 강화할 수 있는 정성 근거

### 3. Manager

역할:
- Quant Analyst와 Event Researcher의 결과를 종합
- 최종 심사 메모와 보고서 형식 정리
- 최종 의견이 과도하게 한쪽으로 치우치지 않도록 일관성 점검

입력:
- Quant Analyst 결과
- Event Researcher 결과
- 기업 기본 정보
- 최종 출력 형식 옵션

출력:
- 최종 심사 메모
- 한줄 판단
- 핵심 위험 요인
- 완화 요인
- 종합 의견

## 입력 번들 설계

다중 에이전트에는 원시 CSV 전체를 넘기지 않는다.
정량 모델과 대시보드에서 이미 정리한 설명용 번들을 입력으로 사용한다.

권장 입력 필드:
- 기업명
- 종목코드
- 시장
- 산업
- 규모
- 회계연도
- 예측확률
- 예측 라벨
- 주요 변수 기여도
- 핵심 재무지표
- 시장/산업 비교 결과
- 뉴스 요약
- 공시 요약

## 출력 원칙

- 출력은 단순 자유서술보다 구조화된 심사 메모를 우선한다.
- 최종 보고서는 대시보드 화면과 연결 가능한 형태를 유지한다.
- 같은 판단을 반복하기보다 정량 근거와 정성 근거를 구분해 제시한다.

권장 출력 섹션:
- 한줄 판단
- 정량 근거
- 최근 이슈
- 핵심 위험 요인
- 완화 요인
- 종합 의견

## 구현 순서

### 1단계
- Quant Analyst 프롬프트 및 출력 템플릿 정의
- Event Researcher 입력 형식 정의
- Manager 출력 템플릿 정의

### 2단계
- 뉴스/공시 수집 파이프라인 연결
- 에이전트별 입력 번들 생성 로직 구현
- 로컬 테스트용 샘플 기업 실행

### 3단계
- 대시보드와 연동
- 심사 메모 저장 및 다운로드 형식 연결
- 시나리오 또는 위원회형 확장 여부 검토

## 이번 문서의 범위

본 문서는 구현 코드가 아니라 설계 합의를 위한 초안이다.
따라서 다음 항목은 아직 포함하지 않는다.

- 실제 API 키 처리 방식
- 실시간 크롤링 코드
- failover 로직
- HITL 세부 동작
- 멀티 에이전트 위원회 토론 루프

이 항목들은 기본 3에이전트 구조가 합의된 이후 별도 구현 단계에서 다룬다.
