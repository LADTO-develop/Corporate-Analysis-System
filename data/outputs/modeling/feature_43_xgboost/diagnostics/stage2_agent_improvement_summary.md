# Stage 2 에이전트 고도화 요약

이 문서는 오늘 진행한 Stage 2 에이전트 고도화 결과를 PR에서 바로 설명할 수
있도록 정리한 최종 요약이다. 중간 반복 실험 파일은 이 문서로 흡수하고, 최종
비교에 필요한 핵심 결과만 남긴다.

## 1. 고도화 목표

1차 XGBoost 모델은 위험기업을 넓게 잡는 조기경보 역할을 한다. Stage 2 에이전트
위원회는 이 결과를 그대로 덮어쓰는 것이 아니라, 다음 두 가지를 보완하는 역할로
정리했다.

- 실제 위험을 놓치지 않도록 `보류/부적격` 검토 대상으로 끌어올린다.
- 모델이 과민하게 경고한 기업은 바로 부적격으로 확정하지 않고 `과민경고 완화 보류`,
  `경계등급 보류`, `확인필요 보류`처럼 판단 유형을 분리한다.

따라서 Stage 2 성능은 하나의 라벨 정확도만으로 보지 않고, 아래 두 기준을 함께 본다.

- `2차 검토대상`: 보류와 부적격을 모두 포함한 넓은 추가 검토 범위
- `2차 위험신호`: 위험 보류와 부적격처럼 실제 위험 경고로 볼 수 있는 좁은 신호

## 2. 오늘 반영한 주요 개선

- `보류`를 하나로 뭉뚱그리지 않고 `경계등급 보류`, `위험 보류`, `과민경고 완화 보류`,
  `확인필요 보류`로 나누었다.
- BBB-/BB+ 주변의 경계등급 기업은 확정 판단보다 추가 검토 대상으로 보이도록 별도
  판단 유형을 추가했다.
- 과거 기준일 이전 공개 신용등급만 사용하는 `prior_rating_reference`를 만들어,
  과거 test/rolling 평가에서 미래 신용등급이 새지 않도록 했다.
- 강한 외부근거가 확인되지 않은 부적격 확정은 보류로 낮추도록 게이트를 보강했다.
- 과민경고 완화 로직을 강화해, 모델이 위험하게 본 투자적격 기업을 바로 부적격으로
  확정하지 않도록 조정했다.
- 배치 평가에서 Stage 2 중복 호출을 제거하고, Agno 실행 시 병렬 처리 구조를 사용해
  체감 실행 시간을 줄였다.
- 대시보드에서는 사용자가 보기 쉽도록 `적격`, `관찰`, `위험 주의`, `부적격` 단계로
  보여주고, 세부 판단 유형은 설명 영역에서 확인하도록 정리했다.

## 3. 성능 개선 요약

아래 30건은 일반 모집단이 아니라 FN, FP, BBB-/BB+ 경계, TP, TN을 섞은 stress test
샘플이다. 따라서 전체 기업군의 최종 성능으로 해석하지 않고, 에이전트가 어려운
케이스에서 1차 모델을 얼마나 보완하는지 보는 평가로 사용한다.

| 기준 | Precision | Recall | F1 | 해석 |
|---|---:|---:|---:|---|
| 1차 모델 | 0.3889 | 0.4667 | 0.4243 | XGBoost 단독 판단 |
| 2차 검토대상(보류+부적격) | 0.5172 | 1.0000 | 0.6818 | 위험기업을 모두 추가 검토망 안으로 올림 |
| 2차 위험신호 | 0.8889 | 0.5333 | 0.6666 | 확정 위험 신호는 더 보수적으로 제시 |
| 2차 부적격만 | 0.8000 | 0.2667 | 0.4000 | 부적격 확정은 고신뢰 근거가 있을 때만 제한적으로 사용 |

핵심 개선은 두 가지다.

- 1차 모델 F1 `0.4243`에서 2차 위험신호 F1 `0.6666`으로 개선되었다.
- `보류+부적격`을 추가 검토 대상으로 보면 Recall `1.0000`이므로, 위험기업을 놓치지
  않는 조기경보 목적에 맞게 작동한다.

## 4. 판단 유형별 의미

| 판단 유형 | 실제 투기등급 비율 | 실제 투자적격 비율 | 해석 |
|---|---:|---:|---|
| 부적격 | 0.8000 | 0.2000 | 위원회가 명확한 위험신호로 본 케이스 |
| 위험 보류 | 1.0000 | 0.0000 | 위험 가능성이 높아 추가 확인이 필요한 케이스 |
| 경계등급 보류 | 0.5714 | 0.4286 | 등급·확률 경계에 있어 확정보다 검토가 필요한 케이스 |
| 과민경고 완화 보류 | 0.2727 | 0.7273 | 모델 경고를 바로 부적격으로 확정하지 않은 케이스 |
| 확인필요 보류 | 0.0000 | 1.0000 | 근거 부족 또는 판단 충돌로 추가 확인을 남긴 케이스 |
| 적격 | 0.0000 | 1.0000 | 추가 위험신호를 강하게 보지 않은 케이스 |

이 결과 때문에 대시보드에서 `보류`를 하나로만 보여주지 않고, 사용자에게는 단계형
판단을 보여주되 내부적으로 세부 유형을 설명하도록 구성했다.

## 5. 경계등급 전용 평가

prior rating이 BBB-/BB+ 주변인 12건을 별도로 확인했다.

| 기준 | Precision | Recall | F1 | 해석 |
|---|---:|---:|---:|---|
| 1차 모델 | 0.3750 | 0.6000 | 0.4615 | 경계등급에서 모델 단독 판단은 불안정 |
| 2차 검토대상(보류+부적격) | 0.4167 | 1.0000 | 0.5883 | 경계 위험을 모두 검토 대상으로 유지 |
| 2차 위험신호 | 1.0000 | 0.6000 | 0.7500 | 확실한 위험신호는 FP 없이 제시 |

경계등급에서는 확정 분류보다 `관찰/보류`가 자연스럽기 때문에, 발표에서는
“경계등급은 Stage 2가 확정 판단보다 추가 확인 대상으로 분리 관리한다”고 설명하는
것이 가장 안전하다.

## 6. 실행 속도 개선

초기 Agno 실행은 케이스당 약 2분 정도 걸리는 문제가 있었다. 오늘 배치 중복 호출을
제거하고 병렬 처리를 적용한 뒤에는 아래처럼 개선됐다.

| 구분 | 케이스 수 | wall time | 체감 처리 시간 |
|---|---:|---:|---:|
| 초기 순차 실행 추정 | 1 | 약 120초 | 약 120초/건 |
| Agno round 3 병렬 실행 | 10 | 259.3초 | 약 25.9초/건 |
| 30건 stress batch 병렬 실행 | 30 | 451.7초 | 약 15.1초/건 |

속도 개선은 주로 다음 두 작업 때문이다.

- 평가 배치에서 `run_once()`와 committee 재호출로 Stage 2가 두 번 돌던 중복 호출을 제거했다.
- Agno 실행에서 Quant/Evidence 역할을 병렬화하고, 배치 workers를 사용해 전체 wall time을 줄였다.

## 7. PR에서 설명할 한 줄 결론

Stage 2 에이전트 위원회는 1차 모델을 대체하는 모델이 아니라, 위험기업을 놓치지
않게 검토망에 올리고, 과민경고는 보류/관찰로 완화하는 보조 판단층으로 고도화했다.
오늘 실험 기준으로 1차 모델 F1 `0.4243` 대비 2차 위험신호 F1은 `0.6666`으로
개선되었고, 보류까지 포함한 추가 검토 기준 Recall은 `1.0000`을 유지했다.
